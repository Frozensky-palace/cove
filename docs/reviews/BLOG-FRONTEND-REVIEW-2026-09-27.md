## 1. 结论

**上一份报告的问题没有全部完成。** 基础整改进展明显，但“有页面、有按钮、有构建检查”还不能等同于“读者可以稳定完成整个操作”。

目前 Cove 已具备完整个人博客的主要页面骨架，不需要推倒重做。下一阶段的重点应从“补页面”转向“打通流程、修复交互边界、统一发现入口”。

最应先处理的五件事：

1. 搜索弹窗的换页重挂载逻辑存在缺陷，首次使用后再进行站内导航，新的搜索入口可能无法打开可见弹窗。
2. 完整搜索页也只返回前 12 条结果，没有查看其余结果的能力。
3. 评论区“重试加载”会被失败后残留的脚本拦住，无法真正重试。
4. 搜索的中文输入、异步竞态、失败恢复和 URL 恢复还未形成完整闭环。
5. 本地新增功能尚不能认定已在正式网站交付：本次刷新线上首页后仍见旧页脚入口，访问 `/tags/` 显示 404。

**本轮前端功能与体验暂评：73 / 100。** 这是独立的新评分，不是对上一轮总分的直接升降判断；未经本地浏览器完整验收，不能作为实测质量认证。

## 4. 下一次发布前优先修复的交互问题

优先级约定：**P0** 为本轮应阻止“前端交互已验收完成”结论的阻断项；**P1** 为核心体验缺口；**P2** 为体验与规模完善。这里的 P0 不代表已确认生产安全事故。

### F01 · P0：搜索弹窗在站内换页后不能正确重挂载

**状态：静态逻辑缺陷，高置信度。**

证据：[SiteHeader.astro:86](../../src/components/navigation/SiteHeader.astro:86)。

首次启动把 `booted` 设为 `true`；随后 `boot()` 一看到该值就返回。`astro:page-load` 虽调用 `boot(false)`，却同样被提前返回。页头没有持久化旧 host，换页后的新 host 无法获得 Vue 实例，旧实例也没有按计划卸载。

**待复现路径：** 首页打开搜索 → 关闭 → 通过站内链接进入文章/笔记 → 再点搜索或按 Ctrl/Cmd+K。新普通链接被拦截，但事件仍交给旧实例，可能没有可见弹窗。

**修改建议：**

- 区分“模块已加载”和“实例已挂在当前 host”，不能共用一个布尔值。
- 在页面交换时卸载旧实例、清理监听；新页面按需要重新挂载。模块可以缓存，DOM 实例不能误当成跨页面持久化。
- 对初始化期间重复点击做并发保护。
- 增加从首页、文章、列表、后退四种路径重复打开搜索的自动测试。

**验收：** 连续换页 10 次仍可打开/关闭；快捷键只响应一次；页面交换后不存在旧弹窗或失效按钮。

### F02 · P0：评论“重试”只是重置文案，没有重新加载

**状态：静态逻辑缺陷，高置信度。**

证据：[CommentProvider.astro:168](../../src/components/integrations/CommentProvider.astro:168)、[重试处理:204](../../src/components/integrations/CommentProvider.astro:204)。

加载失败后原 `script[data-giscus-script]` 仍在。点击重试隐藏错误文案、重新显示“加载中”，但 `load()` 因脚本存在直接返回，没有新请求和新的有效等待流程。

**修改建议：** 用明确的 idle/loading/ready/error 状态管理；重试前清除失败脚本、旧 iframe 与旧定时器，重新注入；避免“iframe 存在”成为唯一成功判断。失败提示直接提供可点击的 GitHub 讨论或邮件入口，不要求读者去页脚寻找。

**验收：** 阻断 Giscus 请求 → 出现错误 → 恢复网络并重试 → 发起新请求并成功；连续重试不会注入多个评论框；离开页面后停止观察与计时。

### F03 · P1：完整搜索页无法访问第 13 条以后的结果

**状态：已核验的功能缺口。**

证据：[search.ts:67](../../src/lib/search.ts:67)、[SearchPanel.vue:90](../../src/components/islands/SearchPanel.vue:90)。

共用搜索封装直接 `slice(0, 12)`，返回值也不包含真实总数。弹窗少量展示合理，但完整页同样截断且没有“查看更多”。结果播报使用截断后的数组长度，超过 12 条时不能代表总匹配数。

**修改建议：** 搜索层返回总数、结果标识与分页数据；弹窗保留少量结果并提供“查看全部 N 条”链接，携带 `q/type`；完整页分页或加载更多，并区分“找到 N 条”与“已显示 M 条”。只加载当前页的结果详情，避免一次取完所有正文片段。

**验收：** 用测试夹具构造至少 25 条匹配结果，所有结果均可到达；刷新保留关键词与筛选；无重复、遗漏或错误计数。Pagefind 的结果 API 支持按需加载结果详情，见[官方 API 文档](https://pagefind.app/docs/api/)。

### F04 · P1：搜索首次加载失败会失去原本可靠的链接回退

**状态：静态逻辑缺陷。**

证据：[SiteHeader.astro:96](../../src/components/navigation/SiteHeader.astro:96)、[search.ts:40](../../src/lib/search.ts:40)、[useSearch.ts:34](../../src/lib/useSearch.ts:34)。

- 页头在动态 import 成功前就设置 `booted`，点击也已 `preventDefault`；没有捕获失败并前往 `/search/`。
- Pagefind 加载 Promise 一旦拒绝，就一直缓存拒绝状态。
- `unavailable` 被设为 true 后没有成功时重置的逻辑。
- 用户会看到“本地执行 pnpm build/preview”的开发说明；正式站网络异常时，该提示既不准确也无法帮助普通读者。

**修改建议：** 加载失败时保留/恢复普通链接；清除失败缓存、提供真正可重试的索引加载；生产提示使用“搜索暂不可用，请重试或按分类浏览”，开发命令仅用于开发环境。尊重 Ctrl/Cmd 点击、新标签页等原生链接行为。

**验收：** 阻断弹窗模块后仍可进入搜索页；阻断索引后显示读者可理解的错误；恢复网络后可重试；正常结果不被旧错误状态覆盖。

### F05 · P1：快速输入与中文输入法存在搜索误跳转风险

**状态：静态逻辑缺陷。**

证据：[useSearch.ts:20](../../src/lib/useSearch.ts:20)、[SearchDialog.vue:81](../../src/components/islands/SearchDialog.vue:81)。

请求序号在防抖结束、真正执行查询时才增加。关键词已经从 A 变成 B、但 B 还在等待防抖的 200ms 内，A 的响应仍可能被接收，让 B 输入框短暂显示 A 的结果。此时回车可能进入错误条目。

弹窗同时直接处理上下键与 Enter，没有检查 `isComposing`。中文输入法选词时这些按键也有用途，不应被搜索抢走。

**修改建议：** 输入/筛选一变化就使旧请求失效；结果携带对应查询版本；候选结果未就绪时不执行跳转；组件卸载时清理防抖计时器。中文合成输入期间忽略导航快捷键，并考虑目标浏览器的 composition 事件行为。

**验收：** 人为打乱 A/B 响应顺序，最终只显示 B；清空查询后不出现旧结果；中文选词回车不跳转，确认输入后再次回车才进入正确内容。

### F06 · P1：URL 同步实现了，但恢复逻辑仍有缺口

**状态：静态逻辑缺陷 / 框架兼容性待验证。**

证据：[SearchPanel.vue:21](../../src/components/islands/SearchPanel.vue:21)。

`readUrl()` 只在参数存在时赋值。URL 不含 `q` 或不含合法 `type` 时，不会主动恢复为空关键词和“全部”。`replaceState(null, ...)` 还丢弃已有 `history.state`，拼接的新地址未保留 hash。不能把“监听了 popstate”就视为前进后退已全面通过。

**修改建议：** 每次读取都完整映射 URL → 状态，缺省/非法值使用默认值；保留已有 history.state 与不应修改的 URL 部分；在合适的提交动作决定是否 push，而不是给每个字符创建历史记录。加入与 ClientRouter 联合运行的回退测试。

**验收：** 测试有参数、无参数、非法类型、清空输入、打开分享链接、离开后后退；界面、URL、结果三者一致。

### F07 · P1：搜索的视觉选择状态尚未成为完整的辅助技术交互

**状态：已核验的语义缺口；实际读屏体验待验证。**

证据：[SearchDialog.vue:129](../../src/components/islands/SearchDialog.vue:129)、[结果列表:183](../../src/components/islands/SearchDialog.vue:183)。

结果声明为 listbox/option，但上下键只改变 `activeIndex`。输入框没有与结果列表关联的 active-descendant 等机制，也没有将真实焦点转移至结果；视觉高亮不等于读屏知道当前选中哪项。当前也缺显式关闭按钮、完整页入口和选中结果滚入可视区域的处理。

**修改建议：** 二选一：采用完整 combobox 交互模型，或采用普通链接列表和真实焦点导航，不混用两种不完整语义。增加明确的关闭操作、结果数量反馈和“进入完整搜索页”。参照 [WAI-ARIA Combobox 模式](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)。

**验收：** 键盘可知当前项、可进入和退出；读屏能播报选中结果；小屏软键盘打开时结果及关闭操作仍可达。

## 5. 功能虽存在，但设计还不够合理的地方

### D01 · P1：发现入口分散，文章列表不像统一浏览中心

证据：[文章列表:35](../../src/pages/posts/[...page].astro:35)、[SiteHeader.astro:24](../../src/components/navigation/SiteHeader.astro:24)、[site.ts:54](../../src/data/site.ts:54)。

标签、系列、归档已可从页脚到达，但桌面文章列表上还没有相应统一入口。进入标签、分类或系列页时，现有一级导航的路径匹配也不一定显示所属栏目，位置感较弱。移动抽屉已包含二级入口，因此不是“全站完全没有入口”，而是不同终端、不同页面的发现能力不一致。

**建议：** 保持现有简洁一级导航；在文章及发现页面增加一致的二级栏：最新 / 分类 / 标签 / 系列 / 归档。详情页有可见当前位置与返回路径。不要把所有入口硬塞进顶栏。基础入口应是普通链接，不能必须先加载搜索才能使用。

### D02 · P1：系列模型把发布时间与章节顺序绑在一起

证据：[content.ts:244](../../src/lib/content.ts:244)、[content.config.ts:54](../../src/content.config.ts:54)、[系列详情:23](../../src/pages/series/[series].astro:23)。

当前系列来自文章上的字符串聚合，阅读顺序等于发布时间；索引主要展示名称、篇数和日期。发布补充章节、调整阅读顺序时，不能独立表达章节位置，也不能展示系列级状态、稳定标识和说明。

**建议：** 增加轻量系列配置或 collection，支持稳定 slug、简介、进行中/已完结、明确章节顺序；保留未配置系列的自动聚合兼容。章节顺序不要靠修改发布日期实现。系列页有“从第一篇开始”和返回系列索引的明确动作。

这是功能模型建议，不要求现在修改文章内容，也不要求加入阅读历史。

### D03 · P2：折叠系列卡混合了“展开”和“跳转”两类操作

证据：[SeriesFeedCard.astro:46](../../src/components/content/SeriesFeedCard.astro:46)。

整个 summary 内含标题、说明、分类链接和标签链接。大区域表示展开，局部又表示跳转，鼠标和触屏用户容易产生操作预期差异；这是交互设计问题，不应简单宣称 HTML 必然无效。

**建议：** 展开触发区仅承担展开；分类/标签等导航移到独立区域。系列名称另有清楚的详情入口。文章列表提供“逐篇时间线 / 按系列组织”切换，默认方式与栏目名称保持一致；同一系列含多篇时明确分页单位是条目还是文章。

### D04 · P1：作者范围内的“查看全部”会变成全站列表

证据：[角色详情:39](../../src/pages/character/[key].astro:39)、[查看全部:120](../../src/pages/character/[key].astro:120)。

角色页文章/笔记/项目列表分别截断为 6/8/6 条，超过后“查看全部”链接却指向不带作者范围的全站索引。只有条目超过上限时才触发，属于规模增长后的潜在路径问题。

**建议：** 指向作者专属列表，或实现可链接的 author 筛选并展示当前范围；若明确只想去全站，改为“浏览全站文章”，不要让文案暗示能继续看此角色的全部条目。

**验收：** 用两位作者各超过 6 条的夹具验证；从角色页继续浏览后不混入其他作者，或文案明确说明范围改变。

### D05 · P1：窄屏目录只能在正文开头访问

证据：[ArticleTOC.astro:29](../../src/components/content/ArticleTOC.astro:29)。

1280px 以下使用正文前的折叠目录。阅读到长文中段后，要切到其他章节需回到开头；该模式也覆盖不少桌面窗口，而不仅是手机。移动目录没有桌面版的当前章节高亮。

**建议：** 仅对有目录的长文提供不遮挡正文的“目录 / 回到顶部”轻量操作，或滚动后出现的紧凑目录入口；统一当前章节状态。两三个标题的短页继续保持简单，不为短文增加浮层。1280px 切换点需按正文与侧栏可用宽度验证，而不是只根据设备称谓。

### D06 · P1：笔记和项目详情的浏览闭环弱于文章

证据：[笔记详情:70](../../src/pages/notes/[id].astro:70)、[项目详情:96](../../src/pages/projects/[id].astro:96)。

文章已具备较完整的继续阅读路径；笔记主要在末尾展示标签，项目主要是外链和相关文章，缺明显的返回同类列表入口。项目列表能显示 `cover`，但详情模板不展示该字段，列表与详情的封面体验不一致。

**建议：** 抽取最小公共详情操作：返回同类列表、复制链接、可选上一条/下一条。长项目说明按标题数量启用目录；按需展示项目封面，不强制复用文章的大封面版式。是否允许笔记/项目评论是产品选择，不算必须缺失。

### D07 · P1：品牌 Splash 为可读内容增加了强制等待

证据：[AppSplash.astro:86](../../src/components/base/AppSplash.astro:86)。

首次会话最少展示 600ms，再等待退场移除计时约 240ms及绘制帧；即使页面已就绪，也不会立即开放阅读。这是源码计时策略，不是本次测得的 LCP。读者直接从外链进入文章时，同样要先看品牌遮罩。

**建议：** 优先在文章深链取消 Splash；首页也不因“保证动画能看见”强制延迟。需要真实加载反馈时使用现有顶部进度。减少动态效果偏好应能跳过非必要停留，而不仅是停掉波浪动画。若保留遮罩，需要验证键盘焦点是否进入被遮挡内容。

### D08 · P1：无 JS 回退没有覆盖“部分 JS 失败”

证据：[BaseLayout.astro:180](../../src/layouts/BaseLayout.astro:180)、[SiteHeader.astro:234](../../src/components/navigation/SiteHeader.astro:234)。

引导脚本先移除 `no-js`，窄屏原生导航立即隐藏，但 MobileNav 岛屿可能尚未成功加载。浏览器能执行少量脚本，并不代表后续模块、网络请求与水合都成功；弱网/分片失败期间可能只剩不能工作的菜单按钮。

**建议：** 以“导航组件已可用”而非“JS 可执行”为隐藏 SSR 导航的条件；或者使用原生 details 导航作为增强底座。把完全禁 JS、模块被拦截、加载慢三种情况都列入验收。

### D09 · P2：页面数量增长后，列表与标签需要规模策略

已核验：只有文章主列表使用 `paginate`；笔记、项目、分类、标签详情、系列索引等没有统一分页/筛选策略。当前条目较少时，这不是立即故障。

**建议：** 用 100 篇文章、100 条笔记、50 个标签的夹具做布局测试。笔记采用分页或加载更多；项目可加状态筛选；标签总览提供标签名定位和数量/名称排序。按栏目实际规模启用，不要为了统一而给 2 个项目强行分页。筛选应写入 URL，并保留普通链接回退。

### D10 · P2：分享和订阅的技术配置完整，用户操作仍较薄

已有 OG 与 RSS，但缺站内“复制链接 / 分享”动作。RSS 入口直接打开 XML，对不使用阅读器的访客缺解释；现有 Feed 只包含文章，不能订阅笔记或项目变化。

**建议：** 详情末尾提供复制链接和支持时的原生分享，处理取消与剪贴板失败；订阅入口先解释如何使用 RSS，并提供复制订阅地址。可按需求增加文章+笔记聚合 Feed，但必须明确订阅范围。邮件订阅需后端、确认/退订与隐私配套，不能只加邮箱输入框。

### D11 · P2：视觉和小交互应补验证，不能靠截图判断全部通过

当前品牌、留白、主题和正文排版值得保留，本轮不建议整体换风格。需要完善的是可验证的细节：

- 搜索过滤按钮最小高度为 36px，标签芯片也较紧凑；建议高频触控操作尽量接近 44px并保留间距。这是易用性目标，**不能仅因不足 44px 就判定不符合所有 WCAG 标准**。
- 测试 320/375px、小屏横屏、200% 缩放、超长标题和英文长词；尤其关注搜索结果的类型/标题/日期三列。
- 浅色与深色分别检查正文、辅助文字、当前项、键盘焦点的对比度；本次没有测量值，不能宣称已经违规或已经合格。
- 404 彩蛋不应让缺失页面看起来像网站临时无人值守或维护；保留明确的“页面不存在”提示与有效出口。
- 打印样式、信息性图片点击查看大图可按实际内容形态增加；自动动效、复杂浮动工具栏不应优先于可靠导航。

### D12 · P1：跨页组件的清理与质量验证仍不完整

证据：[CommentProvider.astro:161](../../src/components/integrations/CommentProvider.astro:161)、[ArticleTOC.astro:166](../../src/components/content/ArticleTOC.astro:166)、[CI](../../.github/workflows/ci.yml)、[package.json](../../package.json)。

评论主题 MutationObserver 没有对应 disconnect；目录每次初始化创建观察器，也没有显式跨页释放；搜索防抖同样缺卸载清理。这些是资源生命周期风险，不能据此声称已测得内存泄漏数值。

**建议：** 统一初始化/销毁边界，按 ClientRouter 生命周期清理实例、观察器、计时器与监听器。参考 [Astro 客户端导航生命周期](https://docs.astro.build/en/guides/view-transitions/)。CI 在现有构建门禁之外，加覆盖真实用户路径的测试；检查远端是否确实将这些检查设为合并必过条件。

### D13 · P2：隐私页没有覆盖实际的会话存储

证据：[privacy.astro:55](../../src/pages/privacy.astro:55)、[AppSplash.astro:62](../../src/components/base/AppSplash.astro:62)。

隐私页说明主题 localStorage 后写“除此之外没有其他本地存储”，但 Splash 使用 `cove:splash-shown` 的 sessionStorage。应说明用途、保存位置和会话范围，或者移除 Splash 存储。这是公开说明与实现的一致性修复，不是本轮法律合规结论。

## 8. 下一轮必须执行的验收场景

| 场景 | 预期 | 建议验证方式 |
| --- | --- | --- |
| 搜索打开后连续站内换页，再打开搜索 | 每页都有可用入口，没有旧实例残留 | 浏览器端到端测试 |
| 索引/弹窗模块加载失败，再恢复网络 | 可浏览、提示准确、可重试 | 请求拦截测试 |
| 搜索匹配超过 12 条 | 总数正确，所有条目可达 | 固定 25 条以上测试夹具 |
| 快速输入 A→B并打乱响应顺序 | 不出现与当前关键词不一致的结果 | 可控异步测试 |
| 中文输入法选词、方向键、回车 | 不抢选词键，不误跳转 | 真实中文输入法手工验收 |
| 搜索分享、刷新、缺省参数、前进后退 | URL、筛选、结果一致 | 与 ClientRouter 联合测试 |
| 评论失败后重试、离开页面 | 有新请求、不无限加载、不重复 iframe | 请求拦截及生命周期测试 |
| 禁 JS / 只阻断 Vue 分片 / 慢网络 | 核心导航仍能使用 | 三种独立降级测试 |
| 320/375/768/1280px、200% 缩放 | 无不必要横向溢出，导航与搜索可操作 | 截图回归+键盘操作 |
| 深浅主题、读屏与键盘全程操作 | 焦点明确、当前项可理解、关闭与返回可达 | 自动检查+手工读屏 |
| 作者内容超过截断上限 | “查看全部”仍保持作者范围 | 多作者测试夹具 |
| 长文中段切换章节 | 不必先回到文章开头找目录 | 手机/窄桌面手工验收 |
| RSS 在实际阅读器中打开 | 正文、链接、作者、更新时间及图片正确 | 阅读器抽查；含相对资源的夹具 |
| 本地版本发布到正式站 | 首页入口、新路由、OG 与搜索索引同版本 | 发布后抽查与版本对照 |

建议将可自动化的场景放入 CI。自动无障碍工具不能替代中文输入法、实际读屏和触屏验收；类型检查、构建成功与断链检查也不能替代上述交互测试。

## 9. 最终建议

Cove 缺的不是更多页面装饰，而是几个关键功能的完整收尾，以及跨页面、跨设备、失败状态下的一致性。

**先修搜索和评论，再统一浏览路径，最后增加分享、订阅说明与规模能力。** 保留现有品牌与静态优先架构，以“读者能否顺利完成一个任务”作为下一轮完成标准。

本报告只新增评审文档，没有修改业务代码、部署配置或上一份报告。
