# 《潮汐之间》｜Cove 交互作品设计方案

状态：探索稿，已由[《靠岸之前》插画短篇方案](COVE-SHORT-STORY-DESIGN.md)替代；尚未实施。日期：2026-10-06。

[扉页视觉方向稿](COVE-TIDES-ART-DIRECTION.svg)与[预览图](COVE-TIDES-ART-DIRECTION.png)展示画幅、层次、色彩与三个形象的关系；最终交互稿仍需按本方案制作分镜和移动端构图。

## 1. 创作主张

**一句话**：首页插画里的小船、灯塔和海浪，分别藏着一段可把玩的海湾；访客通过操纵时间、光和水，发现三者其实在共同写一句话。

作品名为**《潮汐之间》**，落在 Cove 站内独立页面 `/play/`。这是一件有明确谜题和结尾的交互作品，不以分数、排行榜、连续签到或奖励驱动。玩家可以先打开任意章节；每章单独成立，完成三章后，主场景发生一次完整的视觉揭晓。首页仍然是阅读入口，作品只在访客主动点击后加载。

观众的理想感受顺序是：**好奇 → 试探 → 理解一个规律 → 利用规律 → 发现前面忽略的东西 → 愿意停留片刻**。商业完成度来自机制、画面、声音、文案和操作反馈的统一，而非装饰数量。

### 体验目标

- 进入后 5 秒内知道哪里可操作，30 秒内看到一次有意义的因果反馈。
- 每章有一个容易表述的核心动作，以及一次仅靠该动作才能发现的转折。
- 一章约 2–4 分钟；完整体验约 8–12 分钟。随时可离开或重玩，无倒计时和失败惩罚。
- 即使不解谜，也能把场景当作一个有回应的「网页玩具」短暂把玩。
- 通关后的站内内容链接是邀请，不是解锁奖励；不强迫用户从阅读转向游戏。

## 2. 故事与总体结构

主题不是「找到宝藏」，而是**一个地方怎样成为可以靠岸的地方**。三个形象各有一项能力：船能抵达，灯能辨认，潮水能留下痕迹。玩家不是海湾的英雄，而是依次调动这三种能力的人。

| 阶段 | 看到的画面 | 玩家理解到的事 |
| --- | --- | --- |
| 发现 | 首页品牌插画有轻微悬停反馈；点击进入作品扉页 | 插画是一扇门 |
| 选择 | 同一幅海湾的三处可选：小船、灯塔、海浪 | 三章可自由进入 |
| 游玩 | 每章聚焦一个形象和一个操作动词 | 时间、光、水都能改变同一片海湾 |
| 返回 | 完成的章节在扉页留下船位、光束或潮痕 | 行动改变了画面，进度不用文字清单表达 |
| 揭晓 | 三种变化在同一画面中对齐，岸线与光影共同显出「此处可停靠」 | 原本的品牌插画被重新看见 |

最后的文字采用手工排版，不让波浪算法自动拼字。揭晓动画只播放一次，随后保留静态画面；重进页面可从静态完成态重看，也能逐章重玩。最终画面提供「再看一遍」「回到 Cove」「继续阅读」三个清楚的选择，其中阅读链接指向一篇确实适合此主题的已发布内容；上线前由编辑指定，不自动随机。

## 3. 三章设计

### 3.1 小船｜《借潮出航》——时间与航线

**视觉开场**：晨雾中的船停在湾内，前方两条航线分别经过近岸浅滩与外侧深水。时间环刻在画面边缘，像海图的一部分，而非浮在作品上的普通设置滑杆。

**核心操作**：拖动时间环预览一日海况，选一条航线，按「放船」。时间变化会同时改变日光角度、潮位、风向、浅滩范围与帆的姿态。预览时船不动；放船后世界时间按选定速率推进，玩家仍可调快、暂停或倒转。

**谜题编排**：

1. 第一段无岔路，让玩家看到时间与潮水、小船的对应关系。
2. 第二段给出近岸短路：低潮露出路标，但水太浅；高潮水够深，逆风却更强。玩家要发现较短的中间窗口，或选择更长但稳妥的外侧航线。两种解法都有效。
3. 到岸后，一个瓶子从船边漂过。玩家倒转时间，看见瓶子并非从船上掉落，而是在更早时刻从灯塔岸边入海。这是章节转折，不另弹解释框。

**结尾**：船在扉页的安全水域停靠，瓶子的运动轨迹留下一道很淡的线索，提示灯塔章。没有「胜利」大字、星级或计分。

**系统原则**：海况由绝对时间和手工编排的风场函数确定；同一时间值总得到同一状态。航行依确定性路径和浅滩阈值判断。小船在错误选择下会被潮水温柔送回起点，并立即允许重试，不播放漫长失败动画。

### 3.2 灯塔｜《照见来信》——光与遮挡

**视觉开场**：傍晚的海湾，塔身和灯室成为画面唯一高对比焦点。远处有船帆、礁石与一面小反光片。初看是宁静夜景，转灯后才发现物体的影子会落到岸上的纸面。

**核心操作**：转动灯室角度；在第二幕可移动反光片。光束有宽度和边缘衰减，但谜题判定基于明确的角度区间与遮挡关系，避免「肉眼看着照到了，系统却判没中」。

**谜题编排**：

1. 照亮船帆，帆面显出一个半句；玩家理解照明会揭示内容。
2. 直射岸边被礁石挡住；玩家利用反光片绕开遮挡，看见另一半。
3. 两束光看似分别照明，最终却让两道影子在岸上合成一个清楚的「岸」字轮廓。这个字的阴影方向指向海浪章。

**结尾**：灯塔在扉页点亮，光束停在玩家解出的方向。谜题文字和轮廓均需独立手工设计，不能只把预设答案藏在不可见区域。

**系统原则**：用 SVG 场景和少量二维几何计算光线路径；视觉上的柔光与判定用的光线分离。拖动时实时预览，接近正确区域时给逐渐增强的视觉线索，但不自动吸附到答案。

### 3.3 海浪｜《潮痕》——节奏与留痕

**视觉开场**：海面占画幅下半部，岸边有三处被沙覆盖的痕迹。这里没有要躲的障碍，玩家的第一反应应是「我能让两道浪怎样相遇」。

**核心操作**：分别调整蓝色长浪与粉色短浪的起始时刻，按「让潮水来」。两道浪相遇处决定哪一段沙面被冲开。可以慢放、单步推进、撤销和重置。完成谜题后保留自由把玩模式。

**谜题编排**：

1. 第一片沙面容易冲开，露出一道笔画，让玩家理解叠浪不是装饰。
2. 另外两处必须让浪峰错开到不同岸段；玩家学会先观察、再调相位。
3. 三道笔画并非三个字。退一步看，沙痕与灯塔影子、小船轨迹在扉页对齐，共同形成最终文字。这一章不单独展示完整答案。

**结尾**：扉页岸线保留玩家最后一次成功的潮痕；其形状由几套手工校准的状态过渡构成，保证不同屏幕和减少动态效果下都能识别。

**系统原则**：连续波形只驱动画面；解谜使用三处明确的采样窗口和容差。这样视觉足够有生命力，同时不会因设备帧率、浮点误差或拖动速度改变正确答案。

## 4. 美术指导

### 4.1 风格

关键词：**纸面海图、薄雾、水洗、描线、透光**。从现有插画的小船、灯塔、蓝粉双波提取形状语言，制作一套可分层的矢量场景。轮廓保留手绘般的轻微不规则，但操作区域与读字区域必须精确。大块留白承接情绪；高细节仅出现在玩家刚刚改变的地方。

拒绝霓虹发光、塑料质感 3D、密集粒子、不断飘动的背景物、游戏 HUD 的金币与关卡星星。首页继续克制；作品页面允许比正文更有画面感，但必须是访客主动进入的独立空间。

### 4.2 画幅与层次

- 桌面主场景采用约 16:10 的宽画幅，最大内容宽约 1120px；画面、操作和文字提示形成清楚的三层，不叠成一排卡片。
- 手机采用重新构图的竖画幅：主体居中，交互点放大，操作条位于画面下方。不能仅把桌面 SVG 缩至 320px。
- 场景由天空纸底、远岸、主体物、近岸波线、光影、交互反馈六层组成。重要文字用 HTML 覆盖而非烤进图片。
- 扉页固定三个可发现入口。悬停／聚焦只突出当前形象，不让三处同时循环招手。

### 4.3 色彩、字体和材质

沿用站点令牌 `--background`、`--text`、`--cove-blue`、`--shell-pink`。浅色场景以雾白、灰蓝、极淡粉构成；深色场景不是简单反色，而是深蓝灰海面与柔和灯光，保证塔、船和岸线的前后层次。粉色只强调一条关键浪线与少量灯光反射。文本对比度按照站点 AA 口径校准。

标题使用现有系统字栈，通过字距与留白建立刊物感。短句不使用仿手写字体；「手写感」放在海图描线与潮痕，不以牺牲中文字形清晰度换风格。纸张颗粒作为极低对比的本地纹理或 SVG filter，仅在静止时可感，不能闪烁。

### 4.4 动效语法

三章共用一套物理感：小船缓起缓停，灯光转向略有惯性，浪峰先聚后散。操作后的反馈要立即开始，常规控件反馈约 150–220ms；叙事揭晓可使用约 600–900ms 的一次性编排。没有常驻循环漂浮。画面闲置时，世界停在可欣赏的静帧。

时间环的速度只影响作品世界，不影响页面滚动、键盘重复率或站点其他动画。离开作品即停止所有更新。系统开启减少动态效果时，位移与扫光停止，交互结果直接切换；所有谜题仍可通过单步按钮完成。

## 5. 声音与文案

声音是补充层，**默认关闭**。玩家自行开启后使用极轻的三类短音：木质时钟拨动、灯室机械咔哒、潮水落在沙上的低频擦音。关键线索不依赖声音；静音时保留同等视觉和文字提示。音源自制或取得明确授权，文件自托管，不自动播放背景音乐。

文字像刊物旁注，少而准确。建议首次提示：

- 扉页：「海湾里有三件事，可以由你决定。」
- 小船：「拨动时间，再决定何时出发。」
- 灯塔：「光照到哪里，答案就落在哪里。」
- 海浪：「让两道浪在岸边相遇。」
- 完成：「此处可停靠。」

提示系统分三级：先给动作提示，数次无进展后提示规律，再给明确的下一步；玩家可以主动点「给我一点提示」，不突然弹出教学遮罩。文案最终需在原型试玩后修订，不能为维持诗意而让操作含糊。

## 6. 信息架构与交互细则

### 6.1 入口和路由

- 首页 `home-brand.webp` 整张插画成为一个有名称的链接，指向 `/play/`；保留视觉上的小幅 hover 反馈，键盘聚焦时同样可见。图片本身仍可用空 `alt`，语义由链接名称承担；不能再把交互父级设为 `aria-hidden`。
- 页脚加入文字入口「潮汐之间」，使移动端、键盘用户以及从文章进入的访客都能找到它。
- `/play/` 是扉页；`/play/boat/`、`/play/light/`、`/play/waves/` 是可直接分享、可用浏览器后退的独立章节。无 JavaScript 时显示静态场景、作品介绍和返回站点链接。
- 原先考虑的「重播海湾晨雾」可作为扉页次级文本动作单独实施，不与三章完成状态混用；重播不能靠清除 `sessionStorage`，因为现有 Splash 退场会移除节点。

### 6.2 页面框架

每章顶部只有 Cove 返回链接、章节名、三章切换、声音按钮。场景下方依次是主操作、简短状态说明、提示和重新开始。按钮文案指向动作，例如「放船」「让潮水来」，不写模糊的「开始体验」。切换章节保留当前章节的完成状态；未完成的临时操作在返回时从该章起点恢复，避免维护跨路由的复杂瞬时状态。

完成标记保存为带版本号的本地数据，例如 `cove:between-tides:v1`，仅含三章完成布尔值和最后完成时间。用户可以在扉页清除记录；存储不可用时三章照常运行，只是不跨访问保存。不得收集玩家操作轨迹或加入新的第三方服务。

### 6.3 无障碍

- 所有入口和控制均为可聚焦的原生链接、按钮或滑块；触屏有效点击区域至少 44×44px。
- 时间、角度、波形都有清楚的数字／语义状态，如「傍晚，涨潮，近岸可通行」。结果变化通过节制的 `aria-live="polite"` 播报，逐帧变化不播报。
- 光影和颜色之外，谜题线索有文字等价描述；通关不要求拖拽精准落点、听音辨位或限时反应。
- `prefers-reduced-motion` 下提供可完整通关的静态步进模式；暂停动画不是暂停游戏逻辑。
- 键盘焦点不进入纯装饰 SVG 路径；章节切换后焦点移至标题，返回扉页后落在对应形象入口。

## 7. 技术落地

采用现有 Astro 静态输出，章节使用原生 TypeScript、SVG 与 CSS，不新增运行时依赖，不调用远程图片、字体或音源，不修改现有 CSP 放行范围。游戏代码按路由拆分；首页只增加一个普通链接，不加载章节模拟器。

```text
src/pages/play/index.astro
src/pages/play/boat/index.astro
src/pages/play/light/index.astro
src/pages/play/waves/index.astro
src/components/play/PlayShell.astro
src/components/play/PlayScene*.astro
src/lib/play/state.ts
src/lib/play/boat.ts
src/lib/play/light.ts
src/lib/play/waves.ts
src/styles/play.css
public/play/                    自托管且有来源记录的画面／音频资产
```

状态计算和画面渲染分离。小船以绝对时间取样，灯塔以几何交点和手工配置的容差判定，海浪以波形驱动画面、以稳定采样窗口判定。逐帧循环只在当前章活动且页面可见时运行；使用时间戳差值并限制过大步长，避免从后台切回来时船瞬移。Astro 软导航离开章节时销毁循环、事件监听与音频；重新进入只初始化一次。

技术预算作为验收目标：移动端场景操作无明显掉帧；单章自有脚本压缩后力争不超过 45KB、首屏美术与音频分开加载；资源大小以实测网络瀑布为准，不通过降低可读性或删减关键画面硬凑数。音频只在用户启用后下载。低端设备优先减少纹理与绘制频率，绝不改变谜题规则。

## 8. 美术与制作清单

1. 一张能与现有首页卡片辨认为同一世界的扉页海湾矢量分层图；桌面和竖屏各一套构图。
2. 小船、灯塔、双浪三组可独立变形的 SVG 元件，以及远岸、浅滩、反光片、沙面等功能性物件。
3. 浅色、深色、减少动态效果三套关键帧；后两者是设计稿，不留给 CSS 自动推断。
4. 四个关键视觉瞬间的分镜：初入扉页、船倒转时的发现、影子合字、三章最终合景。
5. 自托管音效与授权／制作来源；无声音时的反馈方案。
6. 所有提示、状态、错误、完成与重玩文案，以及站内阅读链接的编辑选择。

## 9. 制作阶段与签收标准

| 阶段 | 产出 | 可以进入下一阶段的证据 |
| --- | --- | --- |
| 预演 | 三章各一张交互分镜、完整结尾分镜、移动端构图 | 三种机制与共同揭晓能被不看说明的人复述 |
| 玩法原型 | 几何图形版三章，先完成小船 | 试玩者能自行发现核心规律；小船倒转的发现确实带来惊喜 |
| 视觉制作 | SVG 分层、主题、排版、光影与材质 | 在真实 320px 手机和桌面上主体清楚、操作不遮挡画面 |
| 工程完成 | 路由、状态、键盘、触屏、减少动态效果、音频 | 三章从直达链接均可完成，软导航来回无重复事件或残留动画 |
| 上线验收 | 浏览器实测、性能与 CSP 检查、编辑校对 | `pnpm check` 与 `pnpm build` 通过；浅深色、静音、存储失败、低速设备均走通 |

视觉与玩法必须一起签收：单纯「实现了三个可操作控件」不算完成。正式验收邀请至少 5 位未参与制作的人试玩，记录他们第一次点击什么、何时理解规则、在哪里卡住、是否注意到最终合景。若多数人需要口头解释核心机制，先改交互，不继续叠特效。

## 10. 范围边界与决策

第一版不做排行榜、每日任务、账号、无限生成关卡、复杂物理引擎或 3D。三章采用手工导演的场景与可重复的确定性结果，确保画面、谜题和文案能被真正打磨。任何新增动效仅存在于访客主动进入的 `/play/` 路由；站点阅读页沿用现有克制动效原则。

此文档是**设计与制作规格**，尚非已实现功能。原型测试可能改变谜题节奏和具体台词，但不改变「时间／光／水三种操作、独立章节、最终合景、无依赖和完整无障碍路径」这一核心结构。
